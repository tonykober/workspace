怪名 ≠ 檔名

模型檔名與遊戲裡的怪物名稱對不太起來，查的時候容易找錯：

  • 黑猩猩 → Monkey　·　大隻的 → Football　·　彈跳怪 → Mummy
  • 盜墓者 → Golden　·　汽車 Boss → CarBoss　·　主廚 → ChampionChef
  • 🔴 正式 Boss 與機械金剛共用同一份 Gorilla（刻意，改一邊兩邊一起變）
  • 🔴 死靈法師的動畫是 Necromancer，但行為跑的是炸彈怪那套

怎麼讀這份表

「行為狀態」是玩法邏輯的狀態（移動、預警、衝撞、死亡…），「clip」是美術實際做的動畫。兩者是多對一：

  • 多數怪只有 walk / attack / dead 三個動畫，卻要撐起 4~11 個行為狀態
  • 例如炸彈人的「預警」「地震跳躍」「攻擊」播的是同一個 attack — 玩家看到的動作一樣，只有特效和時間長度不同
  • playMode：loop 循環播、clamp 播完停在最後一格

🔴 A. 美術做了、但遊戲從來不播（8 支）

這些動畫檔案存在、資料也定義了，但沒有任何程式路徑會播到它們 —— 等於白做的資產，可以回收或接上。

  • Mummy.attack — 木乃伊的攻擊動畫。states 把預警與攻擊都指到 awake02
  • Monkey.fly_out — 黑猩猩離場飛走，實際離場播的是 walk
  • CarBoss.awake（AwakeAnnouncement）— 汽車 Boss 登場宣告，入場實際播 walk
  • ChampionChef.hurt02、ChampionChef.jump
  • Golden.jump_e — 鑽地/落地。目前鑽入與冒出共用同一支 jump_s
  • Golden.jumpatk — JSON 有這個 state，但程式碼從不查它
  • Golden.hurt — 定義了，但 states 把受擊指到 attack（⚠️ 疑似誤植，需確認）

🔴 B. 有玩法狀態、但沒有對應動作（動作缺件）

  • 汽車 Boss 倒車（reversing）— 播的是前進 walk，車往後移動但動畫在前進
  • 炸彈人膨脹（inflating）— 播 walk，一邊走路一邊被放大
  • 大猩猩地震／丟炸彈 — 預警與跳躍都播 dead（大猩猩沒有獨立 idle，idle 與 dead 是同一段）
  • 機械金剛站定（transition）— 同樣播 dead，沒有待機動畫
  • 死靈法師能量彈 — 招牌機制沒有專屬動作，播 hurt
  • 所有怪的入場 — 沒有任何一隻有 intro 動畫，全部播 walk 加程式算高度
  • man/girl/dog/cartonboy/football/monkey 沒有受擊動畫 — 只有閃白

🔴 C. 設定或程式碼異常

  • 紙箱男的三支動畫幀範圍完全相同 [10,30] —— 走路、攻擊、死亡在畫面上一模一樣，實質只有 1 個動作
  • 死靈法師的行為檔是死碼 —— updateNecromancerZombie() 全專案無人呼叫，實際跑的是炸彈怪的行為（蔡 2026-08-19 暫代）。那支檔裡的狀態機一次都沒執行過
  • 炸彈人行為檔裡的 animClip 賦值無效 —— 全專案唯二直接寫 animClip 的地方，但渲染層每幀會覆寫它
  • 黑猩猩的 warning state 是死設定 —— 程式碼查的是 intimidate，在編輯器改 warning 不會生效
  • 死靈法師 hurt 與 dead 起始幀重疊 —— 受擊播的是死亡動畫開頭（⚠️ 需確認是否刻意）
  • 主廚的攻擊會跳格 —— 預警播到 79% 後，發動時倒回第 0 幀重播

✅ D. 已確認刻意，不要當 bug

  • 大猩猩的 attack 與 middle_reward_failure 是同一段資料 —— JSON 的 _notes 有裁示記載：整支 FBX 只有那段有骨骼動作
  • 正式 Boss 與機械金剛共用同一份 Gorilla 動畫與受擊狀態 —— 五處註解一致記載「不拆」。改一邊兩邊一起變是預期行為
  • 木乃伊用 awake02 當攻擊 —— 行為檔有註解確認刻意（但連帶讓 attack 變成沒人播的資產）

❓ E. 程式碼判定不出來，要問企劃

Frankenstein.anim.json 沒有任何怪物引用，states 是空的，extraClips 的 throw/roar01/roar02/swing 也全無引用。是未上線的怪還是已廢棄，看程式碼看不出來。
